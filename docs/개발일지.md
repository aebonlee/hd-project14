# 개발일지

## 2026-08-26 — 첫 구현 · 점검

### 만든 것

엑셀을 올리면 줄마다 검증하고 국가로 권한 다섯 가지를 정한다.
포털 입력은 Playwright 가 대신하되 **최종 Save 는 사람이** 누른다.

### 왜 저장을 자동화하지 않았나

기획서에 "최종 Save 전 검토 단계 필요"라고 적혀 있다.
그 요구가 없었더라도 같은 결론이었을 것이다 —
**포털에 잘못 들어간 뒤 되돌리는 것이 훨씬 번거롭다.**
계정은 지워도 이력이 남고, 권한은 잘못 나가도 눈에 띄지 않는다.

### 매핑에 없는 국가에 기본값을 주지 않는 이유

기본값을 주면 화면은 매끄럽게 넘어간다. 그런데 그 딜러는
**잘못된 권한으로 포털에 들어가고, 아무도 그 사실을 모른다.**
막아 세우면 담당자가 매핑 표에 그 국가를 추가하게 된다 — 그것이 맞는 흐름이다.
`test/logic.test.js` 가 이 규칙을 지킨다(깨뜨려 확인함).

### 이메일 중복을 대소문자 무시하고 보는 이유

`MINJUN.KIM@…` 과 `minjun.kim@…` 은 같은 사람이다.
구분해서 세면 둘 다 통과하고 **포털에 중복 계정이 생긴다.**
예제 엑셀에 일부러 그 줄을 넣어 두었다.

### 점검에서 나온 것

**`guide.html` 이 링크만 있고 파일이 없었다.** 상단 메뉴의 「사용법」을 누르면 404 였다.
index.html 을 쓰면서 메뉴에 넣어 두고 페이지를 안 만든 것이다 —
링크는 만들기 쉽고 페이지는 미루기 쉬워서 생기는 유형이다.
저장소 안 링크를 전수로 대조하는 검사를 두는 편이 낫다.

파비콘·OG 이미지도 빠져 있어 함께 채웠다.

### 아직 못 하는 것

**포털 자동 입력은 완성할 수 없다.** 화면의 입력칸 이름(선택자)을 알아야 하는데
사이트가 사외에서만 열리고 로그인해야 볼 수 있다.
`SELECTORS` 를 비워 두었고, **비어 있으면 스크립트가 스스로 멈춘다** —
엉뚱한 곳에 입력하는 것보다 멈추는 편이 낫다.

확인이 필요한 것 두 가지:
- 로그인 자동화가 사내에서 허용되는가 (계정 잠금 위험)
- 포털이 등록 **API** 를 직접 받는가 — 받는다면 화면을 흉내 내는 것보다 훨씬 안정적이다

## 2026-08-26 (이어서) — 로그인 자동화를 걷어냄

### 왜

기획자 확인: **사내 로그인 자동화 불가, 외부 포털 로그인도 불가.**
"로그인 기능은 임의로 체크하거나 선택하게 해야 함."

앞선 구현은 `HD_PORTAL_USER` / `HD_PORTAL_PASS` 를 환경변수로 받아
자동 로그인했다. 정책에 어긋나므로 **기능 자체를 없앴다.**

### 무엇을 바꿨나

**계정 정보를 아예 다루지 않는다.** 받지도, 저장하지도, 묻지도 않는다.
`.env.example` 을 지우고 스크립트에서 계정 관련 코드를 전부 걷어냈다(참조 0건 확인).

흐름을 이렇게 바꿨다.

1. 터미널에서 **어떤 딜러를 넣을지 고른다** — 전부(`a`) · 일부(`1,3,5`) · 범위(`2-4`)
2. 브라우저가 열리면 **사람이 평소대로 로그인**한다
3. 준비되면 Enter — 그때부터 입력칸을 채운다
4. 한 명씩 멈춘다. 확인하고 **직접 Save**, 그만두려면 `q`

로그인 창을 사람이 쓰므로 계정 정보가 **코드·파일·환경변수 어디에도 남지 않는다.**

### 왜 전부 넣는 것이 기본이 아닌가

고르지 않으면 취소된다. 여덟 줄짜리 엑셀에서 실수로 Enter 를 눌러
여덟 명이 다 들어가는 것보다, 한 번 더 고르게 하는 편이 낫다.

화면에도 **줄마다 체크박스**를 넣었다.
**검토가 필요한 줄은 기본으로 꺼 둔다** — 켜 두면 그대로 내보내기 쉽다.
확인하고 켰다면 그 판단을 존중하되, 내보낸 파일에 `verified` 와 사유를 함께 남겨
나중에 되짚을 수 있게 했다.

### 세션

`launchPersistentContext` 로 `.portal-session/` 에 브라우저 프로필을 남긴다.
다음에 로그인이 유지될 수 있어 편하지만, **공용 PC 에서는 지워야 한다.**
`.gitignore` 에 넣었다.

### 2. Member of Dealer — 절대 자동으로 안 채운다

정식 템플릿의 `Field Guide` 시트를 보면 이 필드는 `Type: Input`, 비고에 **"Search and
select the dealer"** 라고 적혀 있다 — 포털 화면에서 사람이 검색해 고르는 항목이라
엑셀 값만으로는 정확한 딜러를 특정할 수 없다.

여기서 실수하기 쉬운 함정을 하나 찾았다. 기존 `dealer` 별칭 목록에 `'dealer'` 낱말이
있어서, 머리글 매칭이 `"Member of Dealer"` 안의 `dealer` 를 주워 **딜러사명(회사명) 칸으로
잘못 채간다.** 그러면 원래 없어야 할 값이 딜러사명 자리에 들어가 자동화되어 버린다 —
정확히 그가 하지 말아 달라고 한 일이다.

`PASSTHROUGH_ALIASES` 를 새로 두어 `mapHeader()` 에서 FIELDS 매칭보다 **먼저** `Member of
Dealer` 열을 잡아 쓴 칸으로 표시해 두는 방식으로 막았다. 값이 있으면 표·내보내기에
그대로 옮기되 어디서나 "직접 입력값" 이라고 함께 적어 자동 검증된 값과 섞이지 않게 했다.
`test/logic.test.js` 에 이 충돌을 재현하는 테스트를 넣었다(고치기 전엔 실패 확인).

### 3. Region 자동 매핑 — Items to Select 제안

**국가별 권한 매핑(`config/permissions.json`)은 손대지 않았다.** 그가 "코드는 손대지
않습니다, 담당자가 직접 관리하는 표입니다" 라고 명시한 정본이라 이번 기능은 그 위에
얹은 별개 기능으로 만들었다.

유첨2(`config/region-items.json` 로 반영, 164개국 → Region + Account/Authorization 화면의
Items to Select 26개)로 국가 원문 텍스트에서 HD 내부 Region(APAC/LA/MEA/EU/NA/BR/CN/ID/IN)을
찾고, APAC·LA·MEA 면 26개 항목을 체크된 상태의 "제안"으로 보여준다.

**⚠ 이 Region 코드는 permissions.json 의 ISO 두 자리 코드와 다른 체계다.** 유첨2 표에서는
`IN`=인도네시아, `ID`=인도로 ISO 와 정반대다. 두 표를 절대 같은 코드로 착각하면 안 되므로
함수 이름부터 `regionFor`/`hdRegion` 으로 permissions.json 쪽(`normalizeCountry`/`countryCode`)과
구분했고, 테스트로 그 반전을 직접 못박아 두었다.

**국가 열은 영문 전체 이름으로 매칭한다** — 정식 템플릿의 Country 열이 드롭다운으로 그렇게
되어 있기 때문이다(`US` 같은 ISO 코드로는 못 찾는다 — 추측하지 않는 게 맞는 동작이다).
기존 6열 예제 양식(ISO 코드 사용)엔 이 기능이 안 걸리므로, `scripts/make_sample.py` 에
영문 전체 이름(Guatemala → LA)을 쓰는 줄을 하나 추가해 예제에서도 실제로 보이게 했다.

**제안일 뿐 제출이 아니다.** 체크박스는 전부 `disabled` 로 그려 사람이 잘못 눌러 상태가
바뀌는 일이 없게 했고, 화면에도 "포털에서 직접 확인하고 체크하세요" 라고 못박았다.
